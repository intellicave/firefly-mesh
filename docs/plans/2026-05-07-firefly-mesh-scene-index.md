## Reading order

**For someone joining the project:**
1. `meta.md` — what + why + scope (5 min)
2. `ideation.md` — what was decided and what was rejected (5 min)
3. `art/firefly-mesh-art-bible.md` — the visual contract (10 min)
4. `design.md` — the engine architecture (10 min)
5. `plan.md` — what's being built when (5 min)

**For a code reviewer:**
1. `rules.md` — the red lines you should quote (3 min)
2. The PR + relevant section of `design.md` for context

**For an asset PR:**
1. `art/production-pipeline.md` — pipeline steps
2. `art/production-list.yaml` — schema + state
3. `art/firefly-mesh-art-bible.md` — visual contract

## What's in scope for V1 vs not

### V1 (3 weeks)

- `/scene` route inside firefly-mesh dashboard
- 3 views: Org (default), Task (camera-follow), A2A (additive overlay)
- 4 character archetypes × 5 directions × 4 anims = 280 frames
- 4 rooms + 2 hallway tiles
- 6 effects + 4 UI icons
- Read-only data binding via TanStack Query + SSE
- Click-to-drawer integration with existing `<AgentDetailDrawer>`, `<InboxDrawer>`, `<ThreadDrawer>`
- Visual regression baselines + smoke tests

### Out of V1 / future

- 16 character archetypes (palette swap shader for hair/skin variations) → V0.2
- Audit replay view (CRT filter + time scrubber) → V0.2
- Mobile pixel scene (smaller cast, different camera) → V0.2
- Onboarding tour ("the office wakes up at 9am") → V0.3
- In-pixel mutations (drag-to-reassign, in-pixel approve) → V1.0
- Multi-floor offices (>4 departments) → V1.0
- Custom employee customisation (user uploads character sprite) → V1.0+
